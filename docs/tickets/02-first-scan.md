# 02 — 使用者可以將平台上的文件掃描成真實影像

Epic：掃描。User Story：使用者取得可檢視的文件影像。
Blocked by：文件、色彩與精確幾何驗收需要平台放置可對照原稿；目前使用者確認沒有文件。
Status：進行中。Rust 已取得空平台灰階及彩色影像，文件品質與完整設定組合尚未驗收。

配對進度：本機 USB 已正常使用。原始 INQUIRY、端點、灰階／彩色影像與取消後重掃證據見 [硬體紀錄](../hardware.md)。最新擷取範例的能力與影像來自同一個獨占 session。

## 交付與流程

測試呼叫端選定裝置 → 讀取端點與能力 → 驗證設定 → 保留裝置 → 設定／啟動 → 逐塊回傳影像 → 釋放裝置。

## 驗收

- 開啟前後核對唯一目標、VID/PID 與介面，發現不同裝置即停止。不得接管父裝置或 MI_01。
- 讀取真正的 INQUIRY，保存匿名化十六進位紀錄及來源。能力為空、回覆截斷或內容未知時回報錯誤，不能套用假設的預設值。
- 掃描設定只接受實機支援值。拒絕零尺寸、負值、超出平台、解析度無效與計算溢位。
- 先寫會失敗的掃描工作測試，實作後通過，再執行真實影像驗證。
- 驗證灰階與彩色的通道、行序、尺寸、裁切及尾端填補。短讀寫、影像長度矛盾與超限配置由掃描核心終止工作並回報原因。
- 正常完成及失敗均釋放工作資源。測試工具保存收到的影像供獨立檢視器開啟，目視核對測試圖與實體紙張。
- 為 [07 — 掃描明暗品質](07-scan-tones.md)保留同一次掃描在 USB 接收、解碼與轉換後的匿名化對照樣本及設定。明暗修正由 07 驗收，不以取得第一張影像視為品質問題已解決。
- 呼叫端停止接收或回報寫入失敗時，驅動終止工作並回傳錯誤。測試工具儲存遇到既有檔案、權限不足、磁碟滿或寫入中斷時保護原檔，不把部分影像標示完成。檔案儲存不是驅動的使用者功能。

## 測試

2026-09-13：Gray75、RGB75、RGB300、Gray600 完成空平台掃描，逐塊像素與獨立解碼相符。RGB75 第一塊後取消及隨後重掃成功；另一行程存取被拒且原工作正常完成。解析度與像素尺寸、雜湊、來源檔案見硬體紀錄。合成測試涵蓋設定拒絕、框架、短讀、零進度、跨塊行寬、消費端錯誤／panic、取消及清理失敗。這些不能取代原稿目視與幾何驗收。

掃描工作與 USB 交界注入合成回覆及傳輸失敗，另以真實 USB 回覆對照。保存實機解析度、模式、影像尺寸及目視結果。不得把白紙測試當成文字、幾何或色彩品質驗證。

2026-09-13 配對前：能力查詢新增 7 個合成封包測試與 5 個 USB 描述／傳輸長度測試，完整套件共 17 個測試通過。實機 `inquiry` 在找不到 WinUSB 介面時回傳 1。配對後同日實跑改為回傳 0，取得真實能力；仍尚未驗收第一張掃描。
