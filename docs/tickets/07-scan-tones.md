# 07 — 使用者可以取得明暗正常且保留淺色細節的掃描

Epic：掃描品質。User Story：掃描不再出現使用者過去遇到的偏亮偏白問題。
Blocked by：實機重現及修正需 02 的原始影像取得能力，WIA 整合驗收需 05 的可呼叫驅動。來源查核與測試設計可先行。
Status：調查中，尚未重現或修復。

## 已知與未知

- 使用者回報：過去安裝原廠驅動，透過 Windows 掃描操作，彩色有過度曝光感，灰階偏淡。這是使用者描述，尚未由影像數據確認亮部是否已失去細節。原廠驅動版本、解析度、亮度／對比設定與範例影像尚未取得。
- 本次 `wc3119 doctor` 實跑仍回報 MI_00 沒有驅動、問題碼 28、結束碼 2。現有 Rust 程式沒有掃描或明暗轉換，這個狀態無法重現或解釋過去偏白的原因。
- 專案目前沒有可供檢查的 PNG、JPEG、TIFF、BMP 或 PDF 掃描樣本。沒有檢查使用者其他資料夾。
- 已查核 SANE 1.4.0 `xerox_mfp.c` 的模式處理與 SET_WINDOW：threshold 只在線稿／半色調模式啟用。該檔未找到名為 brightness 或 gamma 的實作，不代表硬體不存在相關能力，也不能推論原廠驅動使用何種轉換。

## 區分原因的檢查

彩色與灰階都出現偏亮的描述，因此優先檢查共用亮度設定、明暗轉換及取得影像前的狀態。這是檢查順序，尚不能判定根因，也無法排除個別模式的處理差異。

| 候選原因 | 目前證據 | 能區分原因的檢查 |
| --- | --- | --- |
| 呼叫端要求提亮、自動去背或儲存時轉換 | 已知使用 Windows 掃描，設定未知，尚未證實有這些處理 | 記錄實際要求與有效預設，關閉可關閉的自動修正，對照驅動回傳串流與儲存檔案 |
| 驅動或解碼路徑錯誤，例如值域、通道、亮度曲線或重複轉換 | 現有程式尚無此路徑，原廠實作未知 | 對照同一次工作各階段的樣本，定位最早改變數值之處 |
| 取得影像前的曝光、校正、光學或硬體狀態 | 未取得 USB 影像，不能判定硬體故障 | 原始 USB 樣本已偏白時，核對已知設定並比較暖機後重掃及不同取得路徑 |
| 檔案顯示或色彩描述的差異 | 尚未取得檔案，未證實 | 同一檔案在另一個檢視器比較，檢查實際像素值及附帶色彩資訊 |

亮度正常的另一個取得路徑，可縮小到驅動／軟體差異，但不能僅憑一次比較排除硬體不穩定。原廠驅動若已無法使用，不要求為了比較而重新安裝不可信或不相容套件。

## 重現方式

1. 以同一張含淺灰文字、由黑到白的灰階色塊及彩色色塊的實體原稿固定位置。原稿本身需看得出近白色塊的差異，避免把列印機造成的細節損失歸咎掃描器。
2. 記錄機器暖機狀態、模式、解析度、掃描範圍、WIA 亮度／對比及呼叫端自動處理設定。先測 8-bit 灰階與 24-bit 彩色，再另測二值黑白。
3. 同一次掃描分別保存 USB 樣本、解碼後影像、明暗轉換後資料及呼叫端檔案，記錄各自雜湊及樣本格式。USB 樣本不是未經裝置處理的感測器資料。
4. 在固定色塊區域比較像素分布、各通道平均值及落在最大／最小值的比例。白紙本來就可能接近最大值，不能只看整張影像白色比例就判定過曝。
5. 以重複掃描的波動建立比較容許範圍，結合原稿目視結果決定修正。沒有已知反射值的測試色卡時，不宣稱絕對色彩或亮度已校準。

## 修正與驗收

- [ ] 以對照資料找到最早出現不合理提亮或細節消失的位置，再寫會在修正前失敗的回歸測試。
- [ ] 中性設定保留原始明暗關係，不預設強制去背、自動拉白或套用未經驗證的固定壓暗曲線。若需裝置專用校正，記錄來源、適用模式與量測依據。
- [ ] WIA 亮度、對比符合標準方向及正常值 0，合法範圍、步進、預設值與實際處理一致，無效設定有明確錯誤。無法控制的硬體能力不能假稱支援。
- [ ] 驅動對同一要求只套用一次必要轉換。記錄何處由硬體處理、何處由驅動處理，並區分呼叫端再次處理造成的結果。
- [ ] 淺灰文字與近白色塊不因新增轉換失去原本可分辨的細節，修正偏白也不使暗部壓成一片黑。灰階色塊的明暗順序不得顛倒，RGB 中性色不得產生新的明顯偏色。
- [ ] 對全黑、全白、灰階漸層、各通道極值、空資料、錯誤長度及分塊邊界驗證。合成資料只證明轉換邏輯，不當成真實影像品質證據。
- [ ] 若原始取得的影像已把不同淺色合併成相同值，回報無法由事後壓暗恢復細節，繼續查證取得前的設定與硬體。不得宣稱已恢復不存在於輸入的細節。
- [ ] 同一原稿在相同條件下至少重掃三次，記錄修正前後的色塊數據與目視差異。三次是初始重現要求，不是機器既有表現。
- [ ] 透過既有 Windows 掃描軟體驗證亮度／對比與原稿結果，不新增 GUI。取消、再次掃描及切換模式後不得沿用上一個工作的錯誤校正狀態。

## 目前阻礙與下一步

尚無可讀取影像的 USB 掃描路徑，也沒有歷史掃描樣本，無法判定原廠驅動是否有問題。先完成 02 的影像取得與上述對照，系統驅動變更仍依既有授權規則處理。歷史樣本是有幫助的補充，不是開始新驅動品質驗證的必要條件。
